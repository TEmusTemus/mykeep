# MyKeep Implementation Issue Map

This map defines the implementation issues that will be created after the foundation documents are approved. GitHub assigns issue numbers only when each issue is created, so the future identifiers below are the authoritative dependency references for now. Task 4 of Issue #1 creates the issues in dependency order and replaces each `Pending` entry and named dependency with the actual GitHub issue numbers. Issue #1 is the only existing number used here.

| --- | --- | --- | --- | --- | --- | --- |
| `TOOLING-MONOREPO` | Pending | Establish frontend and backend monorepo tooling | Tooling baseline | Issue #1 | Minimal React/Vite and FastAPI project structure with pinned toolchains and repeatable local commands. | Clean install, frontend production build, backend import, and baseline frontend/backend tests pass. |
| `TOOLING-CI` | Pending | Add CI quality and security gates | Tooling baseline | `TOOLING-MONOREPO` | Pull-request CI for formatting, linting, type checking, tests, builds, dependency/security checks, and secret scanning. | A PR run shows every required check executing and passing; a controlled failure demonstrates enforcement. |

| `PERSISTENCE-STORAGE` | Pending | Configure private Storage bucket and policies | Persistence | `PERSISTENCE-SCHEMA` | Private `mykeep` bucket controls and opaque `members/<member-uuid>/<file-uuid>/blob` object-key policy. | Storage integration tests prove private access, authorized server operations, and cross-member denial without direct `storage` schema changes. |

The dependency order in this map is a delivery gate: work on a dependent issue waits until every prerequisite PR is approved and merged.
