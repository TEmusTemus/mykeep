# MyKeep Implementation Issue Map

This map records the implementation issues created after the foundation documents. GitHub Issue #1 established this plan; Issues #2–#18 are listed in dependency order with their actual issue numbers. A dependent issue must not begin until every listed prerequisite PR is approved and merged.

| Future identifier | GitHub issue | Future title | Milestone | Depends on | Deliverable | Completion evidence |
| --- | --- | --- | --- | --- | --- | --- |
| `TOOLING-MONOREPO` | #2 | Establish frontend and backend monorepo tooling | Tooling baseline | #1 | Minimal React/Vite and FastAPI project structure with pinned toolchains and repeatable local commands. | Clean install, frontend production build, backend import, and baseline frontend/backend tests pass. |
| `TOOLING-CI` | #3 | Add CI quality and security gates | Tooling baseline | #2 | Pull-request CI for formatting, linting, type checking, tests, builds, dependency/security checks, and secret scanning. | A PR run shows every required check executing and passing; a controlled failure demonstrates enforcement. |
| `PERSISTENCE-SCHEMA` | #4 | Create Supabase schema and migrations | Persistence | #3 | Versioned `members`, `files`, audit, and optional session schema with constraints, indexes, RLS, and least-privilege grants. | Migration apply/rollback checks pass, and database tests prove owner isolation and revoked anonymous access. |
| `PERSISTENCE-STORAGE` | #5 | Configure private Storage bucket and policies | Persistence | #4 | Private `mykeep` bucket controls and opaque `members/<member-uuid>/<file-uuid>/blob` object-key policy. | Storage integration tests prove private access, authorized server operations, and cross-member denial without direct `storage` schema changes. |
