# Security Policy

## Reporting a vulnerability

Please report suspected vulnerabilities privately through GitHub's repository security-advisory reporting flow. Do not open a public issue for a vulnerability.

Do not include secrets, credentials, tokens, cookies, signed URLs, private member data, raw LINE user IDs, filenames, object keys, or uploaded file contents in a report. Provide a minimal reproduction, affected component or version, impact, and safe steps to reproduce instead.

## Supported versions

Supported versions will be listed here once MyKeep releases are published. Until then, security reports are assessed against the current default branch.

## Response and disclosure

We will acknowledge a valid report, assess severity and scope, develop and validate a remediation, and coordinate disclosure with the reporter. We will not disclose details publicly until an appropriate fix or mitigation is available, except where earlier disclosure is necessary to protect users.
